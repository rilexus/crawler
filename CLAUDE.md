# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- `npm start` — run the server directly from source (`index.js`) on port 3001 (override with `PORT`).
- `npm run dev` — same as `npm start`, but restarts on file changes (`node --watch`).
- `npm run build` — bundle with esbuild into `dist/index.js` (single-file ESM bundle, targets Node 22).
- `npm run watch` — same as `build`, but rebuilds `dist/index.js` on file changes (esbuild `--watch`). Pair with `npm run start:dist` in another terminal.
- `npm run start:dist` — run the bundled output.
- There is no test suite (`npm test` is a stub that exits with an error) and no lint script. `./test-website-to-markdown.sh <url> [output-file]` is a manual smoke-test script: it runs the full MCP handshake against a server on `localhost:3001` (`initialize` → capture `mcp-session-id` → `notifications/initialized` → `tools/call` for `website-to-markdown`), then JSON-decodes the response and writes the resulting Markdown to `output-file` (default `output.md`). The port is hardcoded in the script, not read from `PORT`.
- Docker: `docker build -t crawler .` builds via a two-stage build that runs `npm run build`, then installs runtime deps (`npm ci --omit=dev`) alongside Alpine's `chromium` package. Note one stale spot in the [Dockerfile](Dockerfile): it still `EXPOSE`s 3000, left over from before the app's default port moved to 3001 — fix or work around this when touching Docker setup.
- The `website-to-markdown` and `extract-information-from-website` tools call out to an LLM for every request, via DeepSeek's OpenAI-compatible API. Configure via env vars: `DEEPSEEK_API_KEY` (required, no default) and `DEEPSEEK_BASE_URL` (default `https://api.deepseek.com`). The model id is hardcoded to `deepseek-v4-flash` in both agent modules. `LM_STUDIO_*` env vars are no longer read anywhere in the codebase.

## Architecture

This is an MCP (Model Context Protocol) server exposing six tools for pulling structured content out of rendered web pages — from raw HTML/element extraction, to persisted CSS-selector scraping, to full LLM-driven Markdown conversion and information extraction.

- [index.js](index.js) — Express app entry point. Calls `process.loadEnvFile()` to load `.env`, then wires the three MCP HTTP verbs (`POST/GET/DELETE /mcp`) to handlers in `mcp-server/index.js`.
- [mcp-server/index.js](mcp-server/index.js) — All MCP transport logic:
  - `createMcpServer()` builds the `McpServer` and calls `server.registerTool(tool.name, tool.config, tool.handler)` for each entry in the local `tools` array.
  - `handlEMCPRequest` (note the typo in the exported name — preserve it unless doing a deliberate rename) handles `POST /mcp`. It uses the MCP `mcp-session-id` header to look up an existing `StreamableHTTPServerTransport` in the in-memory `transports` Map, or creates a new transport + server pair on an initialize request.
  - `handleSessionRequest` handles `GET`/`DELETE /mcp`, requiring an existing session ID.
  - Session state (`transports`) is a process-local `Map`, so it does not survive restarts and does not work across multiple server instances/replicas.
- Each tool module lives one per folder under `mcp-server/tools/<name>/index.js` and exports `name`, `config` (`{ title, description, inputSchema }`, using `zod` for the schema), and an async `handler`. To add a tool, create `mcp-server/tools/<name>/index.js` following that shape and import/add it to the `tools` array in `mcp-server/index.js`. Current tools:
  - [mcp-server/tools/fetch/index.js](mcp-server/tools/fetch/index.js) (`fetch`) — opens `url` and returns the rendered body's raw HTML via `browser.getBody`.
  - [mcp-server/tools/get-element/index.js](mcp-server/tools/get-element/index.js) (`get-element`) — opens `url` and returns the outer HTML of the first element matching a CSS `selector`, via `browser.getElementBySelector`.
  - [mcp-server/tools/save-value/index.js](mcp-server/tools/save-value/index.js) (`save-value`) — persists a `description` plus up to 3 candidate CSS `selectors` for a given `url` to the JSON store, without touching the browser. The saved value starts with `value: null`.
  - [mcp-server/tools/crawl/index.js](mcp-server/tools/crawl/index.js) (`crawl-website`) — loads a previously saved site from the store, opens `url` once, and resolves each saved value's candidate selectors against the live page (first matching selector per group wins, via `browser.resolveSelectorCandidates`), then writes the resolved values back to the store.
  - [mcp-server/tools/extract-from-url/index.js](mcp-server/tools/extract-from-url/index.js) (`extract-information-from-website`) — delegates to `extractInformation()` in the agent module below.
  - [mcp-server/tools/website-to-markdown/index.js](mcp-server/tools/website-to-markdown/index.js) (`website-to-markdown`) — delegates to `generateMarkdown()` in the agent module below. The handler reads a bearer token off the request's `Authorization` header into a local `apiKey`, but currently does not forward it to `generateMarkdown` — the agent always authenticates with the server's own `DEEPSEEK_API_KEY`.
- [browser/index.js](browser/index.js) — centralizes all Puppeteer usage (this replaced the old per-agent "launch and close a browser per call" approach). Lazily launches a single shared `puppeteer` instance on first use (`getBrowser`), and auto-closes it after `BROWSER_IDLE_TIMEOUT_MS` (default 60s, env-overridable) of no active calls; a `disconnected` listener drops the cached instance if the browser dies on its own, so the next call relaunches cleanly. All exported helpers (`getBody`, `getElementBySelector`, `getElementsBySelectors`, `resolveSelectorCandidates`, `fetchBodyHtml`) go through the shared `withPage(url, task)`, which opens a page, navigates with `waitUntil: "networkidle0"`, runs `task`, then closes the page and reschedules the idle-close timer. `getBody` and `fetchBodyHtml` are functionally identical (both strip `script`/`style`/`noscript`/`svg`/`meta`/`link`/`template` before returning `document.body.innerHTML`) — kept as two named exports for the `fetch` tool vs. the agents respectively. When `PUPPETEER_EXECUTABLE_PATH` is set (true in Docker), page launches also pass `--no-sandbox --disable-setuid-sandbox`, since the containerized Chromium runs as root and its sandbox can't start without extra container privileges.
- [mcp-server/store/index.js](mcp-server/store/index.js) — a flat-file JSON key-value store (`get`/`set`/`has`/`remove`/`all`), persisted at `data/websites.json` (created on first write; `data/` is gitignored). Backs `save-value` and `crawl-website`.
- Agent logic (independent of the MCP transport) lives under `agents/<name>/index.js`. Both agents follow the same shape — fetch body HTML via `browser.fetchBodyHtml`, mechanically convert to Markdown with `turndown` (deterministic, no LLM cost, and far smaller than raw HTML), then send that Markdown to an LLM with a task-specific system prompt — and duplicate an identical `createModel()` helper.
  - [agents/website-to-markdown/index.js](agents/website-to-markdown/index.js) — `generateMarkdown(url)` sends the raw Markdown to the LLM to clean it up: stripping leftover navigation/ads/cookie banners/duplicate links and fixing structure.
  - [agents/extract-information/index.js](agents/extract-information/index.js) — `extractInformation(url, informationToExtract)` sends the raw Markdown to the LLM with a prompt scoped to extracting only `informationToExtract`, returning `"Not found."` if the page doesn't contain it.
  - Both agents build their model via `@ai-sdk/openai-compatible`'s `createOpenAICompatible`, pointed at DeepSeek's OpenAI-compatible endpoint (`DEEPSEEK_BASE_URL`, default `https://api.deepseek.com`) with `DEEPSEEK_API_KEY`, using the hardcoded model id `deepseek-v4-flash`. This is a change from an earlier version of this codebase that used a local LM Studio server — no code path reads `LM_STUDIO_*` env vars anymore.

The build produces a single bundled file (`dist/index.js`) via esbuild with a CJS-interop banner (`createRequire`), since some dependencies are CommonJS. `puppeteer` is excluded from the bundle (`--external:puppeteer`) because it resolves its own package/browser paths at runtime and can't be safely inlined — bundling it collides with the banner's `createRequire` and breaks the app on startup. Because of this, the Docker image can't ship only `dist/index.js`: the runtime stage also runs `npm ci --omit=dev` and installs Alpine's `chromium` package, pointing Puppeteer at it via `PUPPETEER_EXECUTABLE_PATH=/usr/bin/chromium-browser` (and `PUPPETEER_SKIP_DOWNLOAD=true` to skip Puppeteer's own Chromium download in both stages).
